# AI-Assisted Backlog Refinement PoC

A small, portfolio-ready proof of concept exploring how an approved AI assistant can help an Agile team challenge a user story before refinement.

**Status:** Demonstration PoC  
**Data:** Fictional e-commerce password-reset example  
**AI integration:** Not connected. The browser demo displays illustrative sample findings; run the prompt in an approved AI tool to capture a real model response.  
**Not a production tool:** No API keys, backend, integrations, or automated readiness decisions.

## Why this PoC?

A story can look complete in a backlog while important assumptions remain unresolved. This workflow explores whether AI can help surface questions about:
- Missing requirements and acceptance criteria
- Hidden assumptions and edge cases
- Security and validation considerations
- Dependencies and delivery risks
- Questions for the Product Owner, developers, and testers

The principle: **Use AI to challenge the story, not simply rewrite it.** The team remains responsible for validating suggestions and deciding readiness.

## Try the browser demo

1. Open `index.html` in a browser, or enable GitHub Pages for this repository.
2. Edit the fictional story and acceptance criteria.
3. Run the sample analysis.
4. Note: the displayed findings are illustrative and rule-based/static, not generated by a live AI model.

## Run a genuine AI review

1. Read `prompts/backlog-refinement-review-prompt.md`.
2. Use only fictional or organization-approved, non-sensitive data.
3. Paste the sample story and criteria into an AI tool approved by your organization.
4. Save the actual response in `evidence/actual-ai-run.md`, replacing the template.
5. Complete `templates/human-review-log.md` to distinguish useful suggestions from items needing team validation.
6. If you revise the story, record the revised criteria and unresolved questions. Do not claim delivery improvements unless measured.

## Suggested evaluation measures

If you test the workflow with real team participation and approved data, you could measure:
- Number of useful questions identified before vs. during refinement
- Number of AI suggestions accepted, rejected, or requiring validation
- Time spent preparing a story for refinement
- Team/PO assessment of usefulness

Use a defined sample and baseline. Do not infer causation or publish improvement percentages without evidence.

## Responsible-use guardrails

- Never paste confidential client, customer, employee, credentials, production, or proprietary information into an unapproved AI service.
- Treat AI output as suggestions, not facts or acceptance criteria.
- Validate security advice with appropriate subject-matter experts.
- Do not let AI make the final Ready/Not Ready decision.
- Remove personal or sensitive information from screenshots before sharing.
